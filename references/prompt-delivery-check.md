# 视频提示词出稿检查协议

适用于新写或修订的视频提示词，包括手动交付和助手写入平台。先阅读[提示词写作与约束](prompt-constraints.md)，用本次确定的内容完成一次专业审稿，再由工具核对准确文本、真实输入与镜头覆盖。本协议不增加审批、试生成或自动提交授权。

## 一次审稿，保留有用依据

以只收到本次正文和附件的模型视角检查：人物、区域和动作是否已经建立对应关系，必要路径、朝向、因果、切镜与声音是否完整，片外安排是否已转成当前可执行的要求。引用承担可见外观，正文承担动态设计和使用边界。审阅图不自动全部上传；每份实际参考都应有独立用途。

普通参考的整体边界放在正文开头、第一处素材标签之前，局部参考职责可在首次使用时说明。暂时忽略边界句，再读动作正文和参考组合：是否仍以依次到达整幅参考构图来组织视频？遇到矛盾直接改原句或参考职责，不能在末尾再加免责声明。严格首尾帧只在本批明确选择且真实入口支持的范围使用，混合输入要分别限定普通参考与严格边界。

声音范围只由[声音计划](sound-plan.md)维护。开头承接本批模型负责的已定声音，核对正文的允许/禁止要求与声音计划在声部、角色和时段上相容；不能保留已定音乐或对白的计划，却在正文同时写全片禁令。不能从现场讲述、没有安排音乐或某人不说话，推成整条静音。模型专用语法按[输入适配](input-adaptation.md)转换，保留完整含义；不要混用其他模型格式或虚构控制能力。

v3 把这次检查留在实际参考职责、已定要求的正文落点和必要接点中，不再要求 `model_scope_review`、`semantic_review`、`positive_review` 三份同义长自评。记录真实依据与仍未验证的部分，不自动填写“clear”或“通过”。

## v3 出稿记录

在 `package.data.prompt_review` 保存下列结构。只列本批真正已定、需要保护的约束，不把所有方法条目抄成要求；确无额外条目时 `requirements` 可为空。

| 字段 | 本版内容 |
| --- | --- |
| `review_version` | `3`。 |
| `prompt` | 将要实际投喂的准确正文，不能是摘要或旧稿。 |
| `reference_policy` | 按实际附件顺序记录 `{id,type,use,mode}`。`type` 为 `image/audio/video/other`；`use` 说明本次采用属性。普通图片 `mode: reference` 另写 `not_required`，说明无需照搬的构图、姿态等。严格边界 `mode: strict_boundary` 另写 `scope` 与 `evidence`，说明具体范围及用户选择、真实入口依据。无附件可为空列表。 |
| `delivery_contract.reference_boundary` | 本批普通图片参考整体边界的准确正文原句。可省略该字段并采用 `prompt_guard.py --policy-text` 返回的默认句；省略字段不等于省略正文边界。严格边界不套相反的排除项。 |
| `requirements` | `{requirement,source,clause,placement?}` 列表：要求是什么、来自哪个已定决定或来源、正文哪句准确承接。`clause` 必须逐字来自正文。确有前置要求时设 `placement: opening`；其余省略。局部改稿保留未改条目，只更新受影响原句及依据。 |
| `continuity_review.units` | 有序 `{id,shot_id}` 列表。`id` 是唯一镜头或阶段标识，`shot_id` 是本次实际包的镜号；同镜多个连续阶段共享同一 `shot_id`。 |
| `continuity_review.joins` | 按顺序覆盖全部相邻单位，每项含 `from,to,type,audience_bridge,evidence,budget_check,status`。依据见[连续性复核](continuity-review.md)，不另建平行表。 |

程序中的 `opening` 指首个非标题文本块，结束于空行、下一标题或第一个真实素材标签。允许开头有 Markdown 标题，允许声音与参考边界用连续多行自然表达；不要求标题、固定句式或字数。正文开始逐图引用或另起镜头段后再写总边界，不能算前置。

下面仅演示结构，不是所有作品套用的正文。场景、声音与动作必须来自本批实际决定：

```json
{
  "review_version": 3,
  "prompt": "保留接杯与杯碟轻碰声，不生成音乐。普通参考图片仅提供人物身份，不作为逐幅到达或完整复现的关键帧。\n\n<node-asset>person</node-asset>提供人物身份。接收方托稳杯碟后，交出方松手。硬切到同一人轻饮，保持同一杯碟。",
  "reference_policy": [
    {"id": "person", "type": "image", "use": "人物身份", "mode": "reference", "not_required": "展示姿态与整幅构图"}
  ],
  "delivery_contract": {"reference_boundary": "普通参考图片仅提供人物身份，不作为逐幅到达或完整复现的关键帧。"},
  "requirements": [
    {"requirement": "保留动作声并禁音乐", "source": "本批已定声音计划", "clause": "保留接杯与杯碟轻碰声，不生成音乐。", "placement": "opening"},
    {"requirement": "接稳之后松手", "source": "本批已定交接动作", "clause": "接收方托稳杯碟后，交出方松手。"}
  ],
  "continuity_review": {
    "units": [{"id": "receive", "shot_id": "SH01"}, {"id": "sip", "shot_id": "SH02"}],
    "joins": [{"from": "receive", "to": "sip", "type": "action_ellipsis", "audience_bridge": "同人同杯，接稳后品茶", "evidence": "本批相邻镜头图中的杯碟与衣袖对应", "budget_check": "切后直接轻饮，不重复抬杯", "status": "unverified"}]
  }
}
```

`resolved` 只表示当前设计接点已解决；`unverified` 表示设计自洽而动态表现尚待验证；已知动作、空间或时长矛盾应为 `design_gap` 并先修正，不能改名为未验证来放行。一个普通单镜可以只有一个 unit、空 joins，不必虚构阶段；真实存在的关键中间过程仍需审查。

## 准备与交付

将准确正文、实际附件、参数和本轮已审的 v3 记录一起写入完整 package JSON，执行一次准备：

```sh
python3 scripts/storyboard.py prepare --directory DIR --input package.json --expected-revision N --compact
```

已有生成包优先用 `read --record-id ID` 定位本次完整输入，再用 `prepare --record-id ID --input changes.json --expected-revision N --compact` 提交局部更新。继承及合并规则见[更新现有生成包](workbench.md#更新现有生成包)，不需要重新手拼整包。

`prepare` 在同一次操作中绑定准确正文及完整输入指纹、校验并保存；输入校验失败不落盘。不必先导出、手抄 `prompt_sha256/input_sha256` 再导出。需要正式文件时可加 `--output 新目录`，保存通过后再导出；若文件导出失败，保留已经准备的版本并明确未导出，可用 `package` 重试，无须重做未变化的语义审稿。记录保存和文件导出不宣称跨介质原子。工具不会代写语义结论，也不会证明来源真实；`expected-revision` 仍保护用户并行修改。旧的 `record/package` 命令保留兼容。

成功的 `prepare` 已执行所需输入检查；常规交接不再对同一包重复跑独立 `prompt_guard`、重复 `prepare` 或额外导出再检查。独立检查命令用于出稿调试、明确报错定位或没有调用 `prepare` 的交付路径。

复用以实际内容和适用范围为依据：正文与声音要求未变且依据仍有效，沿用已审语义；文件字节/版本相同且目标平台、模型、模式和用途适用，沿用已有媒体规格核验；同批路由和授权沿已有决定。只改正文，复查受影响的要求与接点；替换素材，检查新文件及其引用职责；更换入口或参数，核对受到影响的能力和规格。真实目标当前状态仍在写前读取，写后核对实际生效输入，不能用旧回执证明本次平台写入成功。失败按返回的具体问题修复，重用未变化的有效内容，不为消除提示而伪造通过。

独立检查文件可执行 `python3 scripts/prompt_guard.py --input review.json --shot-id SH01 --shot-id SH02`。调用方用 `inspect(review, expected_shot_ids=实际有序镜号)` 传入真实包镜头；只检查自报的 units 不能证明覆盖。相邻同镜阶段合并后，必须与真实包镜号顺序完全相同；遗漏、多出、乱序或绕回都不通过。未传实际镜号的独立检查会提示覆盖未验证。

检查器核验结构、真实标签职责、声明原句是否存在、开头位置及接点覆盖；返回 `ok/errors/review_signals/unverified_joins/prompt_sha256`。它不理解普通参考是否被暗中指定为整幅画面目标，也不能识别所有语义矛盾、遗漏或虚假自评。`requirements` 的完整性和 `clause` 是否保真仍须对照当前已定要求。不能拿“原句存在”、测试通过或 `ok: true` 代替专业审稿和实际结果。

写入平台时只使用已准备包的准确正文、附件和参数。写前读目标最新状态，写后用一次完整回读核对准确正文、实际生效的附件引用与必要参数，包括入口确实消费的生成草稿引用；画布可见连线不能替代实际输入。发现差异只修相关部分并回读受影响项；平台标签变化须同步本包与受影响检查。准备的结束条件与记录收口统一见[视频生产](video-production.md#准备工作如何收口)。不要覆盖用户新稿，不把本地标签当作实际绑定。历史任务保留真实 `submittedPrompt`、任务标识与素材版本，新草稿不会改写旧任务；准备、写入和生成是不同动作，沿用[提交分工](video-production.md#提交分工持续沿用)。`prepare`、`package`检查通过或返回可生成状态只表示输入就绪，不能作为提交授权；平台上的真实任务状态按当前回读如实报告。

## 局部修订与旧版兼容

改一处动作时先比较正文、素材、标签和参数的实际差异，再复核受影响的要求、声音与接点；未变且仍有效的条目直接复用。去掉重复衣服颜色可以继续由实际人物图承载；将“站定后转圈、结束后看屏幕”改成“自然扫描”则丢失已定动作链。将非关键帧边界缩成“不固定动作”也不等义。新增句子同样要检查是否引入未授权要求，不以补齐字段为目标。

同一制作范围内增镜、补镜同样沿本轮反馈直接修订，图稿阶段文字与图片一起更新，不退回文字确认；可复用 `revise` 记录反馈及相关更新。提示词只补受影响的动作、引用与接点，并将新镜号纳入实际包覆盖；不借局部改稿重做未受影响的已采用内容，也不将修改记录冒充新图采用。

未标版本及 v1/v2 记录仍能读取，并返回 `legacy_review` 提示，不追溯伪造历史证据。旧版 `units` 若本身是真实镜号可直接核对；若是镜内阶段，新增 `continuity_review.unit_shots: {阶段ID:实际镜号}` 映射后才能证明真实覆盖。给了实际包镜号却无法匹配时，旧格式同样不能用于新交接。新修订默认采用 v3，不能只改版本号、换哈希或把旧自评自动填成新结论。

## 音频参考的真实规格

仅当本次实际附有音频时，`reference_policy` 的相应项增加 `audio_contract`：`platform,model,mode,checked_at,evidence,file,usage,duration_limits:{min_seconds,max_seconds}`。`file` 指本地实际音频；`usage` 区分整段、片段、声线等职责。有依据的“无下限”写 0，不能将未知下限写 0 绕过；上限未知可以省略，但其余真实规格仍需核对。检查器调用 `ffprobe` 实测文件长度，并拒绝无法读取、超界或上下限矛盾。

声源总长、实际采用区间与视频内时基分别记录；长录音能否截取取决于真实入口，提示词不能承诺精确裁取。新增类型、入口变化或规格错误时才局部复核格式、大小、数量和使用方式，未变的有效依据继续复用。静音补长、重复台词或变速不作为默认修复。

替换音频后回读实际媒体 ID、时长及视频引用，清除仍在消费的旧关系，保留失败任务历史。模型正文只写本次声音用途与必要台词，不夹入上传过程。文件可读、引用成功、参数合规均不等于语音、口型或声音效果已通过。

## 结果才验证制作效果

按真实任务的 `submittedPrompt`、附件、参数和视频时段复查；声音按声音计划实际听检。普通参考任务要看主体身份、结构与动作是否稳定，中间过程是否仍周期性回到参考整图；连续运动要看真实路径、摄影与事件先后，而非检查表有没有填完。

没有新视频，只能报告输入已经修订、平台已经同步或待动态验证。比较多版时核对模型、时长、输入和随机性变化，不把成功归因于一句边界的位置或字数。检查协议能减少明确遗漏，不能保证模型必然服从。
