# 按实际交付与入口组织输入

从现有工作台镜头、已采用记录与本次需求派生package，不建立第二套ShotSpec。导演镜头、镜内阶段、提交包和最终视频条数分别保留；不能为了工具方便偷偷改剧情、切镜或声音。纯文字方案、风格探索和图片任务只完成自己的阶段；无需视频账号、白模、录音或正式package检查。用户只要文本可在对话交付；已有工作台则更新同一数据，不为展示另造真源。

## 图片用途与操作

资产图控制身份或结构；审阅图表达一个具体时刻；生成输入图还必须适合实际入口。可一图多用，不要求每镜三张图。用现有asset.data记录用途和必要的`moment`（起始、接触、变化中、结果）；审阅末态不能自动充当整个动作首帧。

- 新建：补全必要主体、媒介、外观、场景、构图和光色。
- 编辑：真实提供原图，明确局部变化及要保留的属性；有遮罩能力才用真实遮罩。不把“其余不变”说成像素保证。
- 换机位：推导新可见背景、光向与地标关系，不照搬屏幕左右；无来源的新露出部分标作设计延伸。
- 改状态或组合：维持实际采用母图及必要视角锚点，分配独立参考职责；不反复从漂移的末代图独立重设计。结构图按可辨结构验收，镜头图按主次、光色、空间与动作可读性验收。

图稿阶段收到同一制作范围的局部修改或新增、补镜反馈，直接同步修订文字与图片；可用 `revise` 将本轮反馈依据和相关更新一起记录，不退回文字确认。补镜纳入前后接点、实际用图与生成包镜头覆盖，未受影响的已采用内容继续保留。反馈是这次局部修改的依据，不自动代表新图已采用；只有另增业务目标、费用或供应商等越出既有范围的事项才单独澄清。

## 视频输入

在data.input_mode标明实际采用方式（文生、首帧、首尾帧、多参考、参考视频、编辑、延长）；它是本地职责记录，不冒充平台参数。

| 实际方式 | 正文与附件的分工 |
| --- | --- |
| 无图文生 | 写足必要外观、场景及动态；不伪造参考。正式选择文字审阅路径时用review_basis=text_only并记录review_basis_evidence；默认逐镜图流程仍须具备采用图。 |
| 原生首帧/首尾帧 | 使用真实边界输入，文字写从该状态发生的动作。不附相反的“所有图不约束构图”；软构图目标与已执行硬控制分开。 |
| 普通多参考 | 先按独立用途选择实际输入，审阅图不自动全量上传。开头声明整体非关键帧边界，之后按真实标签绑定身份、场景、道具等局部职责，正文完整写动作、摄影、因果及必要变化。可见外观无需重述，看不清、主体辨认或新变化需补足。 |
| 参考视频 | 说明采用的机位、路径或动作及源区间，排除代理材质等无关属性；不把参考当成精确运动保证。 |
| 编辑/延长 | data.source_range记录真实源区间、局部输出时基、边界与变更目标；核对实际入口，不把普通参考当延长锁帧。已有成片的单镜替换另记录经实片核对的repair_context，按[局部返修](video-repair.md)核对前后接点。 |

按已核实模型/模式把限制放到正向正文、支持的负面栏、音频开关、边界或附件中，不臆造参数。开头自然承接本批已定声画约束及普通参考整体边界，再描述局部职责和镜头；不要求固定标题或措辞。声音政策只读取[声音计划](sound-plan.md)，格式适配不能把未安排扩大成禁止，不能丢失已定音效、人声、动作或摄影关系。模型专用语法只在对应入口使用，不混入另一模型字段。去冗余不按长短或禁词数评优。

多镜头包保留实际切点；同镜多阶段保留同一镜号。时间预算不等于模型硬控制。精确节拍、定时图形、编辑变化按真实时基表达，接收/到达成功仍须满足可见完成条件。

内部记录保存授权、费用、版本、审查和后续工序；模型正文只保留能帮助它完成本次声画的信息。内部姓名、区域编号与跨次生成关系必须绑定本次实际参考，或转换为可见对象、地标和起止条件；不能假定模型看过对话。必要背景仍需提供，不把清除内部说明做成删去真实空间依据。来源未知、能力未验证不编造；设计自洽而动态未验可进入获授权的探索，确定设计矛盾先修。

最终正文、实际附件顺序、模式与参数共同按[出稿检查协议](prompt-delivery-check.md)准备和绑定；实际投喂仅采用该版内容。修一处动作时保留未改的已定约束，更新受影响的引用与接点即可。视频生成、平台写入和用户采用各有自己的授权与证据，不因准备通过自动启动。
