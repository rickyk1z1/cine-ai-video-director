# MCP 连接与安装选择

> 详细技术参考，按[制作技术索引](../production-reference-map.md)选择本次需要的部分。当前分镜、已有决定、采用声音和所选路线优先；技术参数应在实际工具与版本中核对。


## 触发时机与最小检查

确定进入 Blender 制作、修改或已约定的必要导出后，首次相关操作前才检查连接。用户专门要求安装、连接诊断或 Blender 技术检查时，也可按其请求执行。创意问答、剧本、分镜、参考图准备不以 MCP 为前提；用户已认可模型与动画、只需交付提示词时不查连接。同一主机、会话和目标 Blender 实例已有有效调用结果且连接未变时直接复用，不因换镜头或小改动重复检查。

白模默认通过MCP制作。先发现当前客户端实际提供的 Blender 工具及参数。用一次轻量只读调用确认响应来自目标实例，并取得 Blender 版本、当前文件路径和场景名；按实际工具能力合并查询。不为测连接建物体、切帧、截图、渲染或扫描整个场景。工具出现在列表、端口开放或安装命令成功，都不能单独证明已经连上目标 Blender。

调用失败或工具不可见时，只诊断相关层：

| 发现的问题 | 下一步 |
|---|---|
| MCP 服务端或依赖不存在 | 确定所缺组件，进入安装选择 |
| 客户端未登记、禁用或未加载工具 | 检查该客户端的 MCP 配置与加载方式，不据此重装 Blender 插件 |
| Blender 未运行、插件未启用或连接服务未启动 | 复用已安装组件，按当前版本启用/启动 |
| 版本、地址或目标实例不匹配 | 核对实际配置和项目目标，只修正有问题的一侧 |

无法取得某层状态时写“尚未确认”，不写“未安装”。MCP不可用时不静默转为CLI制作；明确说明替代路径，并按用户选择或已有授权执行。存在多个实例时先定位目标；不要为探测同时启动多个 Blender。已有可用 MCP 实现就继续使用，不强制迁移到某个品牌或服务名。

## 有缺失时给用户两个选项

先用一句话说明具体缺口和所需操作，再在普通对话正文中提供以下两种方式；不使用系统选择框或问卷工具：

1. **告诉我如何安装**：给出适合当前系统、Blender 版本和 AI 客户端的安装、启用或连接步骤，由用户操作。
2. **帮我安装配置**：由助手补齐缺失组件、配置连接并完成最小连通验证；必要的人工启用或重载步骤单独说明。

只有用户选择第二项或此前已明确授权安装配置，才执行相应安装和配置写入；已有选择持续有效，不重复问同一权限。用户说“开始制作”不单独等于授权新增软件。只是未启用时，将两项表述为“告诉我如何启用/连接”和“帮我启用/连接”，不诱导重装。

## 选项一：交付适配后的步骤

利用现有上下文或轻量只读信息确定操作系统、Blender 版本、AI 客户端和已有组件；仅询问会影响方案且无法获取的信息。给出官方来源、需要安装的组件、具体操作或已代入实际路径的命令、启用位置与成功标志。只补所缺部分，步骤不能停留在“安装一个 MCP”或使用维护者电脑的固定路径。用户完成后，接回最小连接检查并继续已确认的制作流程。

## 选项二：助手安装配置

用户选定后，简述将补齐的组件与位置并直接执行已授权工作。优先使用当前客户端提供的安装工具或 CLI；否则按官方文档配置。工具必须实际可调用，不能假设发布后的所有客户端都有桌面控制、插件安装接口或本地终端。

- 根据实际系统、用户指定的 Blender 版本和客户端能力选择兼容发行版。从官方发布页或仓库取得组件，记录版本和来源；复用合适的运行时，必要时使用独立环境安装服务端依赖。安装位置由目标电脑决定，运行环境不放进可发布 Skill，也不依赖维护者的虚拟环境或目录兼容入口。
- 分别处理服务端、Blender 插件和客户端登记。修改既有配置前留可恢复备份，仅更新目标连接项，保留其他配置。优先用户级安装；现有授权不包含更换 Blender 主版本、付费或大规模下载时，不把这些操作混入 MCP 安装。
- 按该实现的文档配置传输方式、地址和端口；本机连接使用本地接口。不同 MCP 实现的包名、插件 ID、启动方式和工具名不可混用。不修改无关插件或客户端的全局审批策略。
- 插件启用、连接服务启动和客户端重新加载是否可自动完成，取决于当前工具与软件版本。先完成所有可自动执行的工作；若最后仍需用户点击启用、系统授权或重载，只给出必要操作和具体原因，保留已完成进度，不再次询问是否同意安装。缺少本地执行权限的环境可完成方案与命令准备，但不能声称已经代装。
- 串行、小批次执行；不强制退出正在使用的 Blender 或客户端。失败时根据实际错误修复，只有条件改变后才重试，不连续重装、重复启动服务或无限轮询。遇到工具权限限制时如实说明，不绕过限制。

## 当前已核实的安装路径

以下是 2026-09-10 核对的官方路径示例，实际安装时重新核对兼容版本和入口；这些不是固定依赖声明。

- [Blender Lab 官方 MCP](https://www.blender.org/lab/mcp-server/) 由 Blender 端插件、MCP 服务端和支持 MCP 的 AI 客户端配合工作；当日页面要求 Blender 5.1 或更新版本。插件可从 Blender Lab 扩展源或下载后安装；`.mcpb` 包仅用于明确支持这种格式的客户端，其他客户端走服务端源码/运行时安装路径。
- [官方仓库](https://projects.blender.org/lab/blender_mcp) 的已核对 v1.0.0 包要求 Python 3.10+，入口包括 `blender-mcp` 和 `python -m blmcp`。选择此实现时，在独立环境安装适配的官方版本，再把该环境的实际启动命令登记到客户端；不能只创建虚拟环境就报告完成。
- [Codex 官方 MCP 配置](https://developers.openai.com/codex/mcp) 支持通过 `codex mcp add <name> -- <command> ...` 登记本地服务，或更新实际生效的 `config.toml` 中对应的 `mcp_servers` 项。先确认当前 CLI 和配置位置；命令参数、路径按目标环境生成。其他客户端查其官方配置方式，不套用 Codex 的目录或文件格式。

## 连接完成与继续制作

完成安装或启用后，重新发现工具并执行前述最小只读查询；需要重载但尚未完成时明确标为“配置完成，等待加载/连接验证”。只有得到目标 Blender 的有效响应才写“已连接”，随后接回 [Blender/MCP 执行规范](blender-mcp-execution.md) 继续已获确认的制作，不追加创作审批、渲染或动画复核。连接验证只证明可访问目标实例，不证明模型或动画质量。
