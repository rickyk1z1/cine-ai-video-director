# 从剧本到导演方案

> 详细技术参考，按[制作技术索引](../production-reference-map.md)选择本次需要的部分。当前分镜、已有决定、采用声音和所选路线优先；技术参数应在实际工具与版本中核对。


用于剧情、广告叙事、对话、悬念、追逐及动作场面。技术演示只取适用部分；不把所有输入改成短剧、反转或打斗。来源索引见 [research-sources.md](research-sources.md)：D01–D07 为本次实际读取的教学/作者资料，R01–R06 为社区工作流；下面的数据结构与 Blender 应用是本 Skill 的综合设计。

开放想法按 [风格选择](../style-development.md) 理解作品目标与本次范围，已有故事、人物、摄影、声音和资产决定直接复用，不做固定访谈。首次提交完整剧本且目标明确时，同轮给出当前范围的完整分镜和摄影方案。手持程度、长镜头与剪辑取舍按当前叙事提出有依据的主方案；只有会实质改变方向且仍缺失的选择才问，不由题材猜成用户偏好。连续项目先恢复已有设定与进度；项目级保存稳定偏好，不把一次戏的快慢扩展为全剧命令。下面是按需展开的创作分析方法，使用[创作与复核尺度](../storyboard-development.md#创作与复核尺度)。只问实质影响方向的核心缺口，已委托的常规导演选择直接作出并说明，不因表格列出某一维度就要求用户逐项作答。

## 指定风格参照的前置研究与首版实现

用户明确指定影片、创作者、拍摄手法、风格流派或影像样例时，将其要求借鉴的维度作为高优先级创作依据，优先于Skill默认与助手惯用拍法，并服从用户更具体的要求和当前范围。在首版相关分镜与预演制作前，主动研究有关片段、创作者解析或可靠技法资料；已有核实且适用的研究可复用。用户只借鉴摄影时，不自动继承原作人物、剧情或全部美术。

- 选择与本场任务有关的代表材料，记录实际看过的片段/画面、读取的作者说明与设计推断。系列名或宽泛风格不等于所有作品只有一种拍法；只有不同解释会实质改变方案时才补问。资料不可访问时说明替代依据，不能把搜索摘要、图注或播放器存在当作已观看。
- 提炼本次适用的观察距离、机位/景别、主体与相机相对运动、组镜次序、切点、节奏起伏、手持、色光或声音作用。具体焦距、时长和幅度按当前空间与动作确定，不冒充原片实测值。
- 在已有分镜或摄影说明中保留简短对应：`观察到的手法及依据 → 本片用途 → 镜头/时间段 → Blender实现`。先写出相机布置/运动、主体调度与剪辑时序，再在静态认可后的首版动画中实现；不能只写作品名或留到最终生成提示词。
- 制作中的相关预览应能读出所采用的风格特征；色光、完整表演和声音按各自约定阶段承接，不因此扩展简化代理范围。实现受限时说明差异和有依据的替代方案。研究没有固定篇数或观看时长门槛，不增加独立审批；已采用版本仍按原停止条件处理。

## 1. 先解释戏，再分镜

提取用户明确给出的事实、角色目标、障碍、行动和结果；将推断放进 assumptions。已给定的结局、对白、调性和镜头数量优先，不擅自补敌人、反杀、追逐或笑点。

按当前段落选择有用的分析问题，已有分镜表达清楚时不另填同义字段；只把真正影响方向的未决项用自然语言问用户：

- 起始关系是什么，结束时什么发生了变化？可为权力、信任、距离、知识、危险或人物决定；氛围片可用感知变化，不强迫戏剧冲突。
- 每个人此刻试图对谁做什么，遇到阻力后如何改变策略？把“很紧张”转为“藏住手里的东西、试探出口、阻止对方离开”等可表演行为。[D04]
- 观众跟随谁的认知？在哪一刻知道什么、怀疑什么、误解什么？多人信息差难以跟踪时，可登记 audience_knows 与各角色 knows；视点不等于必须使用眼睛位置的 POV。[D01,D06]
- 哪个可见/可听事件迫使下一行为发生？反应是否具有可读的触发原因？

按实际变化拆 beat。一个 beat 可跨多个镜头，一个长镜头也可包含多个 beat；不固定三幕、12节拍、每镜一句对白或若干秒必反转。信息量超过目标时长时，先精简内容或利用同镜头调度，不能无说明把动作整体倍速压缩。

建议节拍表：`beat_id | frame/时间范围 | trigger | character_goal/tactic | visible_action | audience_information_delta | emotional_change | resulting_state`。

需要角色表演时，把意图与情绪落实为事件触发后的可见行动或反应，并延续前后状态。细节密度服从景别、遮挡和停留时间：近景承载读得出的微小反应，远景以姿态、距离或声音表达。补表演沿用已有镜头与事件，不机械给每镜加表情或新增特写。没有情绪需求的产品/机械过程描述操作和反馈即可。

## 2. 选择视点与揭示次序

| 希望形成的体验 | 可选择的处理 | 检查失败方式 |
|---|---|---|
| 悬念 | 提前让观众看到威胁/逃跑意图，再观察尚未察觉的人 | 一开始就解释全部结果，等待段没有新压力 |
| 惊讶 | 限制信息，到事件发生才揭示；提前保证结果在空间上可信 | 为藏信息让关键对象凭空出现 |
| 迟疑、失落 | 让刺激发生后，镜头留给接收者的判断与决定 | 反应未发生就切走，或只有无变化的机械停顿 |
| 追逐紧迫感 | 交代目标、距离、路线或阻碍，动作后果推进下一节拍 | 全程近景和抖动，观众不知谁追谁、距离是否改变 |
| 力量关系变化 | 让距离、站位、遮挡、画面占比随策略改变 | 仅用固定“仰拍强者、俯拍弱者”标签代替情境 |

这是情境选择，不是类型定律。[D01–D03,D06] 基础空间要在观众需要判断行动之前可读；开场可以是细节、反应、画外声或局部，不强制全景。建立镜头也可通过数个局部拼接或同镜头移动完成。

## 3. 镜头必须有工作

每镜的描述应让人理解观看意图、起止构图、主体与相机行动及衔接；已有字段能表达就不另建重复声明。长镜头按需要标内部beat；可以主次明确，也可以有意多中心并置，按实际可读性检查，不强制“一镜只能一种信息”或唯一注意中心。

相邻动作只是同一行为链的阶段、视点与时间连续且没有新的切镜动机时，优先考虑同镜头跟随或重新构图；不能因工作表把“起身/走向/开门”等列成不同任务就自动分镜。是否合并仍服从用户摄影偏好与空间可行性，不强制所有项目一镜到底。

选择拍法时比较静止、运动与剪辑分别能带来什么观看体验，不默认静止最优或要求复杂形式先证明自己不可替代。舞蹈、图形、运动快感和形式实验本身可以是表达理由，须符合当前创作意图；不要每镜自动加轨道运动、呼吸抖动或变焦。[D07]

在已确认的摄影要求内，根据注意力接续、空间连续性、可用时间与实际取景选择切镜、移动或保持机位。主体相邻只是可以连续转移视点的空间条件，不代表必须移镜；能用短距离运动自然接住下一内容时可移动，距离过长、缺少有意义的途中信息或需突出反应时可直接切镜。建立镜头转近景也不自动要求推进。先确定转移目的，再设计路线，不为连接两个机位而挤占内容表达时间。

多人场面在现有分镜动作与声音栏明确谁发起行动或发言、针对谁、谁受到影响及镜头此时观察谁。镜头可以看行动者、接收者或旁观者；各人按已知信息、关系与意图保持连续状态，不自动全员同步或轮流待机。群体反应或叠话仍按剧情安排。表情、视线与手部细节属于成片表演设计，Blender继续按已约定代理范围表达朝向、大姿态及必要时机。

常见镜头工作包括：交代关系、限制或揭示信息、观察决定、显示完整动作、呈现接触/结果、转移注意力、重新交代空间。景别由需要读到的内容决定：手脚接触常需较宽，微小表情需较近，环境造成的威胁可能需要深度关系。

“电影感、紧张、史诗、某导演风格”须转为可观察的 style_contract：观察距离、画面层次、主体占比、静/动比例、相机是否预知动作、运动启动原因、反应停留、声音位置、允许的遮挡与不稳定程度。同时明确主光来源、主辅色、冷暖、饱和度、反差、暗部及肤色、材质和景深；存入视觉设定，分镜引用并标例外。焦段、器材品牌、颗粒和调色词不能独立证明这些效果。

按当前动作段或情绪段判断相邻镜头的功能与变化，而非仅统计全片有哪些机位。重复、静止或长时间停留可以服务于叙事或形式意图；没有该用途时，调整观察方向、距离、相对运动或信息次序。强化某种拍法仍须保留其他已确定的体验要求，不能把一次反馈扩成全片单一机位、统一抖动或固定切换频率。结尾先确定注意力与情绪落点，再分配结果展示和停留时间，不沿用别的项目的收尾秒数。

## 用户可见的分镜交付

使用 [文档模板](production-document-templates.md) 展示当前制作范围的完整表：镜号、时间/时长、实际景别/机位、起止构图、主体动作、主运镜/手持强度、叙事与情绪任务、台词/声音/切点、色光。每行写可理解的拍法，不只写“跟拍”“电影感”或指向内部JSON。随表解释整段节奏，给文件链接，并明确用户可按镜号改景别、手持、长镜头和颜色。

长镜头将多个beat标在同一个镜号下，不把时间切片误写为新机位切换。用户明确要一镜到底时，不因套分段模板自动增加切镜；若实际生成能力需要分段，先解释技术接续与艺术连续的区别。分镜和静态场景的采用范围按 [阶段确认](../workbench.md) 记录，后台文件存在不证明用户已看过。

## 4. 节奏层级、整场节奏与切点

先确认节奏属于哪一层：项目 `screen_language` 只约束画幅、轴线、相机/手持许可条件和长期可读性偏好；`sequence_arc` 描述相邻场次的能量与信息起伏；当前场的 `pacing_profile` 决定信息释放、表演/相机能量、剪辑密度和必要可读窗口；beat 和 shot 才落实触发、行动、反应、实际时长与切点。具体镜头按“用户明确要求 > 镜头例外 > beat > 场次 > 段落 > 项目 > 默认”继承，不能把上一场的对话节奏自动带入后续打斗。

简单段落用自然语言和实际镜头时长说明节奏即可。多场次节奏容易混淆、需要复杂同步或工程消费时，再按需展开 `pacing_profile`：`mode`、`information_rate`、`performance_energy`、`camera_energy`、`editorial_density`、`required_readability` 和按 beat 写出的 `tempo_curve`。这些字段约束观看体验，不是把动画、相机或剪辑机械设置为同一个速度。

方案与动画阶段先安排完整事件、对白和表演所需的表达时间，再联合确定镜头运动与停留。对白无录音时按预期语气估读并标明估计；已有实际朗读或音轨时依据其时长，有明确声画同步要求时再做必要计时。不套统一字速，不因估时自动生成配音或测试视频；无声音输入时将声音线索记为计划，不能声称已混音。节奏由画内运动、表演、声音与镜头时长共同形成。[D02]

区分镜头总时长、转场耗时和主体/信息实际可读的时间；进入某镜头不等于关键内容已经清楚可见。给完整表达、换气和必要反应留出空间，避免镜头刚到位就切走。对白、倾听反应和运动可以交叠，不机械相加；有效表达也不要求全程拍说话者，声音跨镜、画外对白和听者镜头按意图安排并明确声音归属。时间不足时先调整无叙事用途的移动，仍有冲突再在授权范围内重排内容，不靠催快台词补救。已有认可参考时，提示词承接其结构；本条不触发重新编排摄影或追加动画复核。

- 区分事件发生时刻、观众看清时刻、情绪落点和剪辑点；它们可错开。
- 每次切镜提出切点功能：匹配动作、转向听者、兑现期待、主动省略、制造对比或重建空间。动作中切、动作前切、动作后留反应都有适用情境。
- 同方向运动通常可右侧出画、下一镜左侧入画；实际以屏幕速度矢量、动作轴、时间与地理关系检验，不机械要求同边进出。转弯和反向需可读原因。
- 眼线匹配检查真实注视对象及垂直高度；不能只让所有头部朝向相机。
- J-cut 为下一段声音先进入，L-cut 为上一段声音延续；声音可以连接空间或提前触发注意，但不会自动修复动作或地理矛盾。
- 硬切不对两台相机的位置求速度差分。时间省略、重复动作、慢动作使用显式 source time / edit time 映射，不能在连续性报告中当作正常连续时间。

handles 是剪辑余量，readability window 是观众读取信息的时间，simulation pre-roll 是模拟/动作进入状态的准备；三者分别记录。都按动作、FPS与用途设置，不把“2–3帧”当通用观感标准。

对话戏的 `conversational_tension` 可以保持低相机能量、稀疏剪辑和少量位移，同时让信息压力通过视线、停顿、打断和决定逐渐上升；不能因“慢”跳过反应或把无变化的停顿拉长。打斗或追逐的 `action_exchange` 可提高动作和信息密度，但须保留关系/方向、准备、攻击或落空、结果和反应；稳定的关系镜头常比连续近景或摇晃更能让观众读清动作。快切、慢动作和手持可服务事件、视点、感知或形式节奏，不要求每次都由剧情事件触发。

修改场次节奏时，根据实际变更更新受影响的 `pacing_profile`、beat 时间、shot in/out 与切点、角色 Curve 时间映射/事件、相机速度/轨迹、Timeline Marker、连续性状态、轨迹记录及提示词；未受影响的已采用内容继续复用。同步意味着事实一致，不要求全部字段都发生变化。只改相机时保留未受影响的角色动作与对白；只修提示词表达或素材标签时不重建预演。确实改变事件时间或结构时，不能仅全局加速或只改文字而留下相反的旧参考，按 [修订范围](../workbench.md) 处理。

## 5. 排练与审片

沿当前工作流复用原文和已采用风格，先在工作台推敲并确认分镜。采用方案、单独认可静态结果后再写动画；选用圆柱＋球头和4骨骼模板时，它只承担大位移、整体朝向、连续折弯、空间关系和时机。视线、表情、手脚及完整身体协调属于成片设计；简易弯曲不授权详细人体绑定，不把代理平移称为跑动表演已验证。

关键选择不明确时，用少量问题或同一故事的两种短演绎帮助用户决定，说明取舍。已经选择风格可以继续剧本与分镜，但不等于自动采用尚未展示的完整制作方案。用户已采用方案或明确委托相关判断时继续推进，不重复索要已有授权。

用户明确要求 AI 审片时，围绕其问题选择以下观察方式，不默认分三次看完整段：

1. 正常速度：能否读懂谁要什么、发生什么、为何进入下一动作？
2. 停格/慢放：检查眼线、遮挡、接触、运动与切镜连续性；不能据慢放清楚就认定正常速度可读。
3. 声画关系：有声时检查触发与重音，无声时检查视觉因果；依赖声音的剧情不强制静音也能完全理解。

验证范围与结论必须匹配：`Fast` 只做制作/修改中的必要局部数据检查，不能判定节奏或导演质量；`Standard` 用于用户明确要求的指定画面/镜头复核，`Release` 用于用户明确要求的完整技术验收，不因阶段完成自动触发。用户已认可当前模型和动画时，按 [用户确认与视频提示词交付](../video-production.md) 直接交付，不追加导演审片。未执行项目保持 `unverified`，不把脚本通过称为节奏通过，也不要求 AI 再确认用户判断。

优先修复叙事理解与动作因果，其次构图、节奏和表演，再加外观。删掉某镜头或相机动作做对比，观察是否损失必要信息、情绪或形式意图；若无损，可简化。报告分清结构可检验项和审美评价，不把完整字段或文件校验当导演质量通过。
