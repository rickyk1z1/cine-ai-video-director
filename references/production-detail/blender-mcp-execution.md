# Blender / MCP 执行规范（1.5）

> 本地适配自TYGG AI Film Studio v3.2.7，详细技术参考，按[加载与输出映射](../tygg-reference-map.md)使用。现有主Skill的用户选择、确认节点、已采用声音及所选实现路径优先；不继承来源中的新增授权。版本/性能数字属于来源记录或启发式，执行时核对本机。


本规范用于制作、修改和用户明确要求的 AI 检查。用户已认可当前模型与动画时，优先执行 [用户确认与视频提示词交付](../video-production.md)：直接进入交付，不自动进入任何验证档位；已有视频复用，缺少已约定参考视频时只完成必要导出，不把导出变成复核。

## 发现与官方适配

只在确定进入 Blender 制作/修改/已约定的导出，或用户明确要求连接诊断、Blender 技术检查时，按 [MCP 连接与安装选择](blender-mcp-setup.md) 发现并验证连接。正常连接直接复用；缺失时区分安装、启用、客户端加载与实例选择问题，按用户选择提供步骤或代为安装配置，不统一重装。

先发现工具名、参数、响应再读场景。TYGG记录的Blender Lab MCP v1.0.0映射如下（非本机连接证明）；其他版本重新发现。

| 需求 | 官方工具 | 边界 |
|---|---|---|
| 场景/对象/存档 | get_objects_summary、get_object_detail_summary、get_blendfile_summary_datablocks、get_blendfile_summary_path_info | 优先专用只读工具 |
| API/手册 | get_python_api_docs、search_api_docs、search_manual_docs | 版本差异用运行时RNA复核 |
| 画面 | get_screenshot_of_area_as_image、get_screenshot_of_window_as_image | 截图不是FPS |
| 建模/相机/动画/GN/统计 | execute_blender_code | 缺专用工具时使用明确bpy代码，返回JSON result |
| 渲染 | render_thumbnail_to_path、render_viewport_to_path | 后者v1.0.0实际调用当前引擎render，不保证Solid playblast；实际返回路径可能为Blender临时目录，取返回值再复制进工作区 |

scene.patch、camera.keyframe、timeline.set_cuts、validate.scene、job.cancel都是概念能力，不是该官方MCP真实工具。没有原生dry-run/事务/取消时不能伪造调用或自动回滚。

## 写前预检

记录request_id、版本、seed、目标scene/collection、允许改的对象、预期计数、文件和预算。检查模式/单位、命名冲突、RNA枚举、依赖、禁止模式（逐草Object、未批准Realize、每帧重建、全局purge）。默认人物脚本按 [尺寸与弯曲标准](character-proxy-standard.md) 创建圆柱＋球头及4骨骼和隐藏控制对象；可见操作镜头按 [简化手部IK](contact-hand-ik.md) 追加计划内的接触附件；不得因剧本动作词扩大为全身四肢、详细人体骨架或多套姿态代理。静态阶段绑定休息姿态，动画沿用本范围已取得的继续制作决定；静态与动态实际采用分别记录。细小表演转写视频正文。

原生dry-run可用则用，否则静态编译/参数验证+只读查询，标local_static，不代表运行成功。用户已授权清理当前项目可执行；只清理目标scene，跨scene共用对象只解除当前scene链接，不顺带删除磁盘文件或用户偏好。

读取审核过的工作区脚本纯文本作为execute_blender_code.code发送，不把剧本/资产描述/网页直接拼代码。标准操作优先bpy.ops，批量数据或避免副作用时用data API。修改器按需要选择，应用前查共享data用户。

使用稳定ID和可重入命名：同名先查归属并更新/退出，避免.001重复。每阶段返回真实diff/count/warnings/errors/路径。错误或超时先查部分完成状态，不盲目重放。长渲染有限帧；主线程长循环冻结UI，分批或短timer回调，结束/失败注销。无实际任务API不得声称可可靠取消。

## 图片资产与曲线位移

环境或关键道具写入前，按 [图片流程](reference-image-driven-assets.md) 核对本批必要结构图：真实可用、已登记且已认可，或复用已有可靠资产依据。人物图另为最终视频准备，缺失不阻挡代理制作。图片提取项与路径作为记录，不将外部文本拼接成代码。

建模先拓扑/净空，再可识别轮廓、关键部件、接触面和有限细节，重复物实例化。保存并实际向用户展示静态结果，按 [Blender预演](../blender-previs.md) 承接该范围的继续制作决定。已有静态认可或用户明确要求直接调整完整运镜时继续写动画，不追加重复许可；一般的建模许可不自动扩大为动画制作。继续制作授权不冒充未发生的静态采用，静态与动态实际采用仍分别记录。静态与动画不得捆在同一批不可中断请求里执行。

按 [联合路线](blocking-and-camera-paths.md) 声明 `motion_owner`。自主行进默认 Curve / Follow Path，保留可编辑控制点；纯搭乘采用已声明父级，静态无需 Curve。只对本批控制来源、切换和相关障碍做必要检查，避免双重位移。未支持的来源与无法读取的动画明确记未验证，不默认为空曲线或已通过。

TYGG记录的Blender5.2实测GN修改器输入为 `getattr(modifier.properties.inputs, socket_identifier).value`；旧版常用 `modifier[socket_identifier]` 在5.2可能报“不支持IDProperties”。先查RNA并做版本适配，不猜Socket编号。接口默认值与实例修改器当前输入不是同一数据。修改参数后标记宿主对象update_tag并更新视层再测。在支持 layered Action 的版本中， 将 F-Curve 放在 `ActionLayer -> ActionKeyframeStrip -> ActionChannelbag`，不再直接读取 `Action.fcurves`；路径/root-motion 检查必须按对象的 `animation_data.action_slot` 读取对应 Channelbag，并保留旧版 Action 的兼容分支。

## 分级验证、变更范围与缓存

验证不是每次都跑完整预览。每轮变更先登记 `change_scope`、受影响的稳定 ID、`revision`、所用验证档和未验证项；只重做能被该变更实际影响的检查。执行请求和结果解释见 [快速验证](fast-validation.md)。`Fast`、`Standard`、`Release` 是检查范围，不能代替实际结果；任何档位都不得将未实现或未执行的检查写成通过。

| 档位 | 触发条件 | 检查范围 | 边界 |
|---|---|---|---|
| `Fast` | 制作或修改中需要检查受影响数据 | 与变更有关的约束/曲线、显式代理采样碰撞、声明主体点屏幕投影；按实际需要选项 | 不跑完整帧序列、真实 FPS、全场性能或渲染 |
| `Standard` | 用户明确要求 AI 查看指定模型或镜头 | 围绕所问问题使用现有画面、视口或少量关键帧；确需新图时才选 Workbench 或轻 Eevee | 阶段完成不自动触发；不默认生成全部首/中/尾、全场审计或完整视频 |
| `Release` | 用户明确要求完整技术验收或全片 AI 复核 | 按请求查看完整正常速度预览与连续性；性能或真实播放测量仅在请求涵盖且可测时执行 | 用户认可或提示词交付不触发；不默认高样本离线渲染 |

将本轮必要的结构检查合并为一次有采样上限的 `execute_blender_code` 调用，返回结构化 JSON 中的检查、错误、警告和范围；不按对象、约束或帧逐条 MCP 往返。快速脚本会临时切换采样帧并恢复原帧，不修改创作数据；它不包含全场性能审计。用户要求的视觉检查优先复用已有画面，数据检查不能冒充截图或正常速度播放。查询报错或超时后先读取部分状态，不盲目重放写入或渲染批次。

`validate_previs_fast.py` 的请求必须只列出本轮受影响的 `affected_shot_ids`、角色、静态 `collision_objects` 与必要的 `risk_frames`。默认每6帧加镜头首/中/尾采样，`max_samples` 默认96；即使显式传入 `sample_frames` 也会统一裁到场景帧范围和该上限。相机速度、加速度与 jerk 只在同一镜头内部计算，硬切不会被误报成相机运动。错误的半径、缺失的路径或不支持的动画数据结构必须输出明确的检查问题，不能让整次审核中断。

该脚本只做结构采样。碰撞采用显式声明的静态代理与球体对 AABB 的宽相初筛；缺少代理或采样之间的穿越不在结论范围内。主体投影和可选遮挡射线只覆盖声明的点，不能证明全身可见或构图合格。完整网格碰撞、变形后圆柱的支撑、脚滑、轴线、表演与电影感均没有由该脚本证明；简单弯曲支撑仅按实际局部检查记录，未测写`unverified`。详细人体步态/手脚检查对默认代理记`not_applicable`。

以下变更范围决定制作/修改中的必要局部检查，不用于用户确认后追加复检：

- 参考图、拓扑、门洞、障碍、轮廓或尺度变化：检查受影响净空、通行和相机构图，展示修改结果；按已有修改授权继续相关制作，不因内容更新重走文字或静态许可。新版本的实际采用按用户对结果的选择记录。
- 角色 Curve、停步/转身或角色尺寸变化：检查相关路径、约束唯一性和碰撞；道具变化则检查其位移、旋转、接触锚点与归属事件，不重审未改区域。
- 仅相机路径、焦段、目标、切点或遮挡策略变化：检查受影响构图与切点；复用未变的几何统计和已认可镜头，不强制重新生成缩略图。
- GN 密度、实例、LOD、修改器或渲染设置变化：仅在变化会影响负载或用户报告卡顿时，做必要的局部性能检查；不据此默认重新审完整场景。
- 剧本、分镜、场景关系或动作因果变化：递增 revision，按新合同确定受影响范围；用户接受修改后直接进入 `prompt_export`。

缓存是证据复用规则，目前脚本没有实现持久缓存或自动失效系统。可复用硬件档案、参考图登记、静态审片图、镜头缩略图和性能结果，但须记录来源 revision、证据路径/检测范围、相关资产/镜头依赖及适用的 Blender/GPU/引擎/视口配置。跨 revision 复用时补充本次引用版本与“哪些依赖未改”的依据；仅版本号递增不必重测，相关依赖改变或无法确认时标为失效。不得将旧来源改写成新测量，或据旧证据证明新路径、遮挡与连续性通过。复用已导出的画面时，另记录来源版本、源帧与当前帧的对应关系及未变依赖；仅重新导出实际受影响且需要交付的范围，不能只凭修改时长很短就认定其余画面可复用。

## 预算、预览与保存

预算用 [performance-budget.md](performance-budget.md)，资产用 [asset-library.md](asset-library.md)。查询当前RNA再设Eevee/采样/透明/阴影，别照搬旧BLENDER_EEVEE_NEXT。镜头分轨迹/跟随/构图/风格层，cuts绑定Timeline Markers。

`Fast` 不调用渲染工具。用户请求视觉复核时优先使用现有图像或视口；只有所问问题无法看清时才生成少量预演分辨率图像，按目的选择 Workbench 或轻 Eevee。全片输出用于已约定的视频交付或用户指定完整复核；缺视频可先给条件稿，但任务含参考视频时仍须完成该产物。输出成功也不证明无穿模。具体按 [视频交付](reference-video-delivery.md)。用户要求控制负载时，Blender 写入、检查和渲染串行、小批次执行；不并行启动多个 Blender 或渲染进程，不自动提升采样或 GPU 负载。

局部修正无效或重复出现同一问题时，保留证据并重新诊断原因、控制来源与影响范围，停止重复同一种无效方法。在已有授权范围内选择有依据的可逆调整继续推进，不以达到固定修复次数本身作为必须重新取得许可的理由；缺少新依据、遇到实际阻塞或需要改变已锁定创意及授权范围时，报告具体限制和可选方案，不盲目继续试改。不得无上限重渲或用反复全片导出来寻找局部问题。保存新工作区blend，用户明确覆盖才覆盖旧文件。临时校准恢复原场景/帧/相机/选择/播放；用户要求当前项目替换或保留则保留结果，不自动删除。实际FPS未测保留未验证状态。
