# 按镜头启用的简化手部 IK（规则 3.2.0）

> 本地适配自TYGG AI Film Studio v3.2.7，详细技术参考，按[加载与输出映射](../tygg-reference-map.md)使用。现有主Skill的用户选择、确认节点、已采用声音及所选实现路径优先；不继承来源中的新增授权。版本/性能数字属于来源记录或启发式，执行时核对本机。


这是圆柱＋球头与4骨骼弯曲代理的可选接触附件，仍属于结构预演。目的只是在必要镜头表达哪只手接触哪里、物体由谁持有、何时操作或释放；不升级为完整人体表演，也不把“任何肢体参考都必然有害”写成模型定律。

## 按分镜决定，不按动作词一律建手

| 镜头需求 | 默认采用 |
|---|---|
| 驾驶、稳定持物、递接、按压或开门，手与物体的接触在画面中可见且影响理解 | `contact_ik`：按需要建立单侧或双侧简化手臂与掌块；稳定接触可以只保持姿态，不必增加摆动 |
| 手在画外、被可靠遮挡或太小，主体位置与道具轨迹已能说明关系 | `none`：隐藏锚点与道具变换即可，不因“拿着”自动加手 |
| 跑步、打斗、快速挥击、扑咬等激烈动作 | `none`：优先整体位移、朝向、圆柱弯曲、道具事件与结果；不制作摆臂、拳路或粗糙抓挠循环 |
| 一个连续镜头从稳定接触转入激烈动作 | 保持代理几何连续，先完成释放/交接；已出现的手臂保持简洁且与身体相连，不补激烈摆臂，不在可见时突然消失 |

分镜阶段在对应镜号记录判断、左右手、目标道具及接触区间，普通文字告诉用户此处用手帮助表达操作即可，不要求用户选择IK参数。按手部实际操作判断：车辆高速行驶仍可以是稳定驾驶接触；“跑着持物”不自动要求摆臂，关键道具的归属和轨迹仍须保留。已确认制作范围中的必要简化接触属于默认策略，无需额外授权完整人体。用户明确要求全程无手或详细肢体时，按其选择和范围记录。要求仅在某段出现局部肢体时，限定所需时段和可见范围，同时保持所属角色、进入来源和退出方向可辨；不自动扩成常驻手臂，也不把最小模型做成无来源的悬空附件。

纯激烈动作镜头通常直接使用无手代理。对已存在的附件，只有原有切镜、自然遮挡或画外边界允许安全切换显示；不得为切换添切镜、替换整个姿态模型或让可见手臂弹出/消失。连续画面没有隐藏机会时保留简单附件，接触结束后随躯体保持低活动姿态。不能留下T姿、悬空掌块、绑定错位或未完成动作，再指望提示词必然消除。

## 最小模型与比例

保留同一个圆柱与球头。每个需要的手侧只增加上臂、前臂两个低面短圆柱/胶囊和一个无独立手指的掌块；不要只放一只悬空手。单侧最多增加3个可见网格；两侧需要时共享网格数据，保持各自控制。不增加肩球、手肘球、指节、皮肤、指甲或衣袖细节，使用同一角色识别色。

长度沿角色设定和现有H/W/L参数确定并跨章记录。可用的美术起点：肩连接点在躯体左右侧约`x=±W/2, z=0.93L`，上臂长`0.17H`、前臂长`0.15H`，臂直径约`0.05H`；掌块长/宽/厚约`0.075H/0.055H/0.025H`。左右手按角色自身方向命名，不用屏幕左右推断。儿童、异形或已定造型可调整，这些不是解剖标准或必须填满的细节预算。

连接点随上躯干骨段变形；先按真实接触空间安排站位/座位和道具，再作合理比例调整。静态接触先核对人物与载体的前向、支撑面朝向及可达关系，再调局部IK。坐姿按骨盆落点、坐垫和靠背支撑、上身方向判断，不能只看旋转角的正负；区分腕端、掌面与抓握点，端点到目标很近仍可能手腕反折。不能为碰到方向盘无限拉长手臂、缩放身体或移动既定道具。已有`derive_proxy_dimensions.py`只计算基础两个体块与4骨骼，不包含此附件的网格或骨骼预算。

## 绑定与控制

1. 在同一角色Armature内，每侧追加`UpperArm`、`Forearm`、`Hand`三个简单骨段。上臂根以偏移父接到`TorsoUpper`（不强制连接到其骨尾），前臂接上臂，掌块绑定Hand。网格绑定相应骨段；角色根位移/转向只继承一次，不再叠加同一条路径或双重父级补偿。
2. 在前臂设置腕端IK目标，链长明确为2，仅求解上臂和前臂；关闭拉伸。单独的极向目标确定肘部弯曲方向，初始姿态略弯，避免共线奇点及极向翻转。掌块以独立末端朝向控制保持握持方向；腕位置目标与掌心接触点有偏移，不能直接把手腕中心吸到物体表面。
3. 所有IK目标、极向目标、抓握锚点和骨架均不渲染。极向目标依附稳定的身体/载体空间；接触目标归属由动作决定，不能因身体移动而漂离应固定的物体。
4. 每个时段给道具和手指定唯一主导来源。驾驶：方向盘/操作件驱动其上的握持锚点，IK手追随锚点。持物：独立握持控制器驱动手目标及道具偏移。递接/放下：在接触成立时更换控制来源，保存世界变换并保持接触时间一致。不要把道具父接到手，同时又让手的IK目标父接到该道具，形成依赖循环。
5. 优先保持IK控制并移动/交接目标空间；不默认制作整套IK/FK切换系统。确需转换来源时先匹配切换帧的世界位置和朝向，保持段长和过渡连续，不能只改Influence期待自动无跳变。

IK链长、极向目标与拉伸参数的含义参考 [Blender 5.2 KinematicConstraint API](https://docs.blender.org/api/5.2/bpy.types.KinematicConstraint.html) 和 [Blender IK说明](https://docs.blender.org/manual/id/5.0/animation/constraints/tracking/ik_solver.html)。执行脚本时仍核对目标Blender版本的实际RNA能力；上面的比例、附件数量与动作范围是本Skill的制作选择。

## 制作、记录和交付

静态阶段创建所需附件、绑定与接触摆位，不写动画，和场景一并展示。已批准静态模型后临时新增附件，只展示这个受影响的静态改动，不重走全项目；已有同范围明确认可直接复用。动画阶段按实际操作设计可读的接近→接触→保持/操作或受阻→解除→退出及结果状态与必要跟随，不附赠指法、腕花、闲置摆手或呼吸手抖。先联合安排主体站位、肢体可达范围与障碍变化，确认进入和退出通路，再精调腕端与掌面；末端位置准确不能代表整条手臂有通过空间。

沿用项目字段，在SceneSpec顶层可选`contact_hand_plan`或关联文档中记录。关键操作另用简短文字或已有字段明确每只手对应的道具/接触面、动作起止状态、依据与核实范围；分镜、控制对象及提示词使用同一关系。人体侧别从主体自身解释，R/L对象名不能替代该关系的核对。既有记录足够时不补新必填字段：

```yaml
contact_hand_plan:
  - character_id: CHR_01
    shot_ids: [SH_010]
    mode: contact_ik # 无需可见接触时使用none，并写原因
    sides: [left, right]
    purpose: "驾驶时双手与方向盘保持可读接触"
    target_ref: PROP_STEERING_WHEEL
    phase_range: "按本镜实际帧段填写"
    control_owner: prop_grip_anchors
    continuity: keep_attached_within_continuous_shot
    dimensions_ref: canon/character-proxies.json
    status: planned # 仅示例，不能充当已创建或已验证证据
```

制作中仅在受影响的接触和交接帧段检查主体手别与道具分工、肩连接、目标可达、肘翻转、上臂/前臂/掌块与障碍的体积关系、控制循环和世界变换跳变；优先覆盖进入、转向、最窄处和退出，不只看稳定接触姿态。发现问题后有界细查有关区间，不扩大为全场逐帧检查；有限采样不证明全过程无相交。无详细指骨就不检查指法。用户已明确的手别纠正应直接进入现行记录与正文，不改成“原来的那只手”回避明确要求。画面不清或命名相反时分开记录来源及未验证范围，不让模型自行解决矛盾。`validate_previs_fast.py`不验证这条手部IK链、掌面接触或交接正确性；没有实施的项目记为未验证。用户认可动画后不再增加AI复核，后续文字一致性按 [写作核对](ai-video-and-asset-prompts.md#写作核对与按反馈修订)处理。

按实际片段写`@视频N`职责：有简化手部时，仅采用手—物接触位置、持物归属与操作/释放时机，不采用杆状手臂、块状掌形、僵硬握姿和未设计的摆臂；自然手指、抓握与发力依剧本和人物图表现。没有手部预演就不要谎称视频提供了手部轨迹。纯跑动/打斗段明确由正文完整描述自然摆臂和动作细节；不把“预演没有做手”写成成片人物不能用手。
