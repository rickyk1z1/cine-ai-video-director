# 制作文件与采用视频的默认位置

用于新作品建工作区、视频结果下载、返修及用户确认采用时。按文件的**实际职责与采用状态**决定位置，不凭扩展名或文件名里的“最终”猜测。已有项目明确采用的目录优先；同一作品沿用一次选定的归属，不由每个会话再造一套目录。多会话交接要传同一个项目根、作品ID和分镜工作区。没有必要文件时不建空目录。

## 一份工作数据，两类媒体位置

有明确项目根时，缺省结构为：

```text
项目根/
├── 分镜工作区/<作品ID>/  ← 实际工作区名称可沿项目已有安排
│   ├── storyboard.json、分镜阅览.md、制作记录.md
│   ├── 制作输入/        ← 当前提示词、参数、生成包与附件映射
│   ├── 分镜图/、资产/    ← 确实制作的图稿和可复用素材
│   └── 过程记录/        ← 预演白模、调试视频、抽帧、检查与过程回执
└── 视频素材/<作品ID>/
    ├── 候选/<实际run或稳定批次ID>/  ← 平台原始下载与该版必要检查资料
    └── 采用/                       ← 用户最终选定的可交付视频素材
```

`分镜工作区` 是示意，不要求新项目都叫“分镜”。项目之外的独立任务，以当前作品工作区为根，在其中使用 `视频素材/候选/` 与 `视频素材/采用/`。路径只在首次归属时确定一次，之后按真实项目位置继续使用。可用只读 `python3 scripts/media_paths.py --directory WORK_DIR --project-root PROJECT_DIR --work-id WORK_ID [--run-id RUN_ID]` 取得新项目的默认路径；没有项目根时省略 `--project-root/--work-id`。`WORK_ID` 是该作品在项目中的稳定标识，优先沿用已经使用的编号，不用会话名或日期代替作品身份。脚本只计算路径，不建目录、移动文件或决定是否采用。

网页/Blender白模、运动预演与代理视频若只是运镜或空间依据，归工作区 `过程记录/`，即使格式为MP4也不是平台生成候选或成品。平台生成但尚未采用的原始结果归 `候选/<run>/`；保留真实run、平台任务、实际提交输入及声画检查。补镜和返修同样先进入候选，新旧结果保持可回查。

## 确认采用时的收口

用户明确采用后，才把本次实际采用视频放入该作品的 `采用/`。推荐文件名 `作品ID-生成段或镜头组ID-采用-vNN.mp4`；整部作品一次生成可省略中间ID。文件名用于寻找，不决定状态；多个生成段分别采用时各有明确编号。必要的原生声轨、技术参数和可播放性检查仍按当前交付要求执行；下载完成、后期试剪或代理预演不自动采用。

原始下载仍可留在候选run目录作任务证据。采用文件与它字节相同时，同一文件系统上可以创建经哈希核对的硬链接，避免重复占空间；环境不支持时才复制一次并核对字节，不能以更名覆盖原始来源。`result` 的当前 `files` 指向采用区的实际视频，记录采用依据、覆盖镜头、包及任务版本、原始下载位置与SHA；旧版本保留历史。`storyboard.json` 仍是采用状态的唯一制作真源，阅读稿由它派生；已有项目总览只链接本次真实采用路径，不另维护一张独立“最终版”清单。多种分辨率或超分版同时存在时写清实际交付采用的是哪份，另一个版本不因文件名被自动视为当前成品。

已有作品原本把采用视频放在其他有效位置时，保留真实文件及记录；本规则从后续新结果开始使用，不为整齐批量搬迁已确认媒体。用户确需迁移时，逐项核对任务、制作记录、后期工程和PPT等消费者；按[工作台搬迁映射](workbench.md#阅读文档与文件组织)保存旧到新路径及SHA，回读实际采用结果后再移除旧路径。不能只搬文件并留下失效引用，也不能把独有原始文件当缓存清掉。
