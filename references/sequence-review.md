# 自动整段图序预演与审查

用户确认当前范围全部分镜图后，助手自动完成本批唯一一次整段内部检查。按实际采用图片、镜头顺序和预计时长看完整段，判断观众能否理解行动、空间、信息揭示和节奏。给出建议后，即使结论是待修改，整段审查也已经完成。后续进入建议落实与生成方式选择。用户按建议人工调整后，没有再次审查环节，也不让助手重新评审其方案；只更新受影响的生成建议、引用材料与投喂输入。它不增加一次用户批准，不要求用户填表，也不自动启动 Blender、付费生成或视频任务。

这次整段审查发现能从图上看出的矛盾、缺失信息或无效重复时，给出当前图稿阶段的文字与图片修改建议；不退回文字审批，不撤销既有进度与授权。范围、重大取舍或新增生成费用超出既有授权时，仍沿实际授权边界处理。

## 实际怎样看

1. 从当前工作台导出 `rehearsal.manifest()`，使用工作台预演入口查看其中的采用图。镜头沿文档中的真实顺序，候选、弃用、缺失与已经失效的图不混入采用序列。组图按已有格子裁切查看。
2. 按当前镜头时长完整看一遍，先不用备注替画面解释，观察观众此刻能知道什么、为何进入下一画面、切换后需要多久才能辨认。然后回看必要的首尾与镜内状态，结合原文、声音设计和观看目的定位具体缺口。已定声音只是设计依据，没有播放的音频不能声称听过。
3. 按[连续性复核](continuity-review.md)判断信息、因果、视点、空间、动作和构图关系。检查全段是否成立，也检查关键动作的中间信息是否真的可以省略。缺口优先在已有镜头、调度、揭示时机或时长内解决，确需新信息才补镜。
4. 将实际发现与整段判断写入一条 `decision_type=sequence_review` 制作记录。复用同一份 v3 `continuity_review` 接点依据，不另造导演、技术、模型三套自评。此次同时给出针对真实镜头的生成方案推荐：建议哪种投产方式、使用哪些已有参考、怎样组织本段镜头，以及限制与未定选择。推荐在工作台供用户选择，不能替用户确定路线或启动生成。助手填写真实判断；程序只检查范围、材料是否改变以及记录是否覆盖实际序列。

没有有效时长时，仍可逐张看图并查出明显缺口；清单保留全部可用图片，明确计时未完成，不给镜头偷偷套默认秒数。一个镜头有多张状态图时，它们是该镜头内部的状态依据，不自动成为独立镜头。自动轮播若均分展示时间，只是浏览辅助，不能将均分值写成已设计的动作节奏；应按镜头总时长和实际阶段安排审查。

同一采用记录的 `files[]` 本来是有序列表，默认沿用其顺序。明确的 `state_start/start_frame` 与 `state_end/end_frame` 标记将首尾放到对应位置；确有另行编排时，可由助手在文件条目添加唯一数字 `sequence_order`。跨多条记录且无法判断状态顺序时，清单返回具体问题并保留图像，由助手补齐顺序依据，不要求用户另批一次元数据。

## 最小记录与接口

`scripts/rehearsal.py` 不写生产状态、不调用平台、不渲染视频，也不新增依赖。

```python
current = rehearsal.manifest(doc, root, section_ids=None, shot_ids=None)
```

返回当前选择方式 `scope`、实际有序 `shot_ids`、逐镜 `frames`、`adjacent_pairs`、`fingerprints`、完整范围 `fingerprint`、`issues` 与 `limits`。每镜包含时长、内容、首尾状态、衔接、声音、真实采用图路径、文件哈希及已有裁切框。未知时长及其后的累计时间为 `None`。`source_fingerprint` 单独标记当前原文与创作意图；镜头指纹同时包含其相关分镜文字、节奏、图片内容、段落/组备注及共同来源。

记录沿现有 `kind=decision` 格式建立，`shot_ids` 对应清单，`data` 只需：

```json
{
  "decision_type": "sequence_review",
  "review_version": 3,
  "manifest": {
    "scope": {"section_ids": ["本段ID"], "shot_ids": null},
    "shot_ids": ["SH01", "SH02"],
    "fingerprint": "复制本次清单的 fingerprint",
    "fingerprints": {"shots": {}, "joins": {}}
  },
  "summary": "填写实际观看发现、整段是否成立的判断与仍未实测的部分。",
  "result": "revise",
  "continuity_review": {
    "units": [{"id": "接稳", "shot_id": "SH01"}, {"id": "品茶", "shot_id": "SH02"}],
    "joins": [{
      "from": "接稳",
      "to": "品茶",
      "type": "action_ellipsis",
      "audience_bridge": "同一人持同一杯碟，接稳之后进入品茶。",
      "evidence": "填写本次实际首尾图片中支持或反驳这一关系的证据。",
      "budget_check": "填写前后时长如何支持辨认与动作；未知处保留。",
      "status": "design_gap"
    }]
  }
}
```

此例故意没有代填通过结论和哈希；`manifest` 中四项从本次真实清单原样复制，`fingerprints` 不能留空。`summary` 和接点依据由实际看图的助手填写，`result=revise` 表示这次审查提出了建议，也永久保留整段审查已完成的事实。用户后续人工修订由现有 `revise` 记录留据，标明变更部分未经第二轮整段审查即可；不要求将旧结果改成 `ready` 才能继续。`ready` 表示本次静态图序与节奏设计审查可用，不是用户采用、生成授权或视频效果通过。

v3 `units` 必须依序精确覆盖本次实际镜头；同镜必要的连续阶段可以有多个单位，但它们的 `shot_id` 保持同一真实镜号。`joins` 覆盖所有相邻单位。可确认的设计缺口写 `design_gap` 并修正；设计已自洽、仅真实运动或生成服从性待验时才写 `unverified`。`resolved` 也只对应所列依据，不能外推为未做过的动态验收。

```python
# 查看原审查完整范围；会按保存的 scope 重新展开当前镜头。
rehearsal.validate_review(doc, record, root)
# 可选查询：原判断还覆盖当前投产包的哪些镜头和接点，不是人工修订后的审批门禁。
rehearsal.validate_review(doc, record, root, shot_ids=package_shot_ids)
```

返回 `{ok, issues, unverified_joins, limits}`。调用者只从当前有效、未被替代的记录中选择审查；不能用整条历史记录的通用过时状态，把无关镜头变化连带到已验证的局部包。

## 变化只影响相关范围

逐镜指纹绑定当前文字、时长、实际文件内容和裁切；相邻接点指纹同时绑定两端与顺序。改图、调时长、修改动作、重新排列或新建接点后，相关指纹变化，表示原判断不自动覆盖新方案；不表示必须重新审查。未变化的局部可以继续复用已有审查。删除中镜形成的新切点不能借原有两个接点取得通过。

全段审查用 `section_ids` 或全项目范围保存 `scope`，这样能准确识别新增镜头与原判断的覆盖差异，不会误称旧结论已经覆盖新方案。确实只审指定局部时可用 `shot_ids`，但其结论只覆盖所选局部，不能声称已审整个段落。改动共同原文、创作意图或共享备注会影响对应依赖；单改显示镜号或标题不自动推翻图片内容审查。

人工修改后，助手不再对用户方案启动语义评审。指纹差异只用来避免沿用旧材料或冒称原结论覆盖新方案；更新生成建议与投喂输入时，只检查实际文件、范围、引用、平台规格等必要技术一致性。未经第二轮整段审查是如实的证据边界，不是继续制作的阻塞。整段审查完成事实、仍有效的采用与授权始终保留；只有新作品或真正另立批次才建立新的整段审查。

文件读取缓存仅存在于一次不可变读取期间，不跨编辑保留。静态时序预演与可选的 Blender/空间预演是不同工作：本步骤不要求先做三维，也不能证明空间运动、表演、口型、混音或最终视频的效果。真实生成视频仍按正常速度完整观看、实际试听及准确切点验收。


## 明确需要局部复核时的可选工具

```python
updated = rehearsal.update_review(doc, record, root, shot_ids=changed_ids, evidence={
    "summary": "实际核对了哪些调整与前后接点，原建议如何落实，剩下什么。",
    "continuity_review": amended_existing_continuity_review,
    # 仅在实际局部检查支持时由助手明确填写；省略则保留原 result。
    "result": "ready",
})
```

只有明确需要局部复核时才使用此纯函数，不是每次人工修改后必须走的步骤。返回同一审查的更新记录，由调用者沿已有工作台保存流程写入。保留首次 `summary`，更新受影响镜头/接点的当前指纹，并在 `local_updates` 追加本次范围、实际依据、前后指纹与结论变化。它不会猜测 `ready`，也不生成新的整段审查或批准。首次待修改、后续可交接的过程由首份总结与局部更新历史共同保留。

`continuity_review` 沿用原表，仅改受影响单位与接点；助手复制未变部分，不让用户重填。新增、删除和重排的镜头列入 `changed_ids`，函数将前后接点纳入局部核对；涉及其他镜头的结构变化时，具体指出需纳入的局部。没有变化的镜头文字/图稿指纹保持原值，不因无关镜头另有变化就把它们自动盖章为最新。

可选局部复核返回的缺口只属于该次明确复核的结果。指纹失配只说明材料与所查版本不同，不清空整段审查完成记录、不重置阶段、不撤销授权，也不要求对用户人工修订再次评审。人工修订的后续准备依据是当前 `revise` 记录和必要技术一致性检查。生成方案建议是随镜头更新的活信息：初稿给初步建议，本批唯一一次整段审查时汇总具体模式、输入、分组和成本风险，人工修改后只更新受影响建议与投喂输入；用户已做出的有效选择继续沿用。
