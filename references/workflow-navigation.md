# 当前工作、下一步与修订

续做先读 `storyboard.py current`。`workflow.next_actions` 是页面与助手共用的下一步，覆盖制作、参考请求及协作落实；`workflow.scopes` 保留各范围阶段与细节。它们都从同一份已保存记录派生，不是新队列或审批表。缺项提示说明助手接下来做什么，不能用“已检查”字段冒充创作判断。

| 当前工作 | 完成依据与下一行动 |
| --- | --- |
| 理解与设计 | 先读 `workspace.visual_style`，未定时在工作台看图比较并保存；已定方向直接回显。复用有效素材，明确观看目的，再将文字、具体路线与缺口一起呈现 |
| 必要输入制作 | 按已选方式准备输入，必要母图先采用再派生；合法无图路径跳过绘图 |
| 图序审查 | 适用且本批尚未完成时做一次；已完成后人工改动不重新启动审批或语义评审 |
| 视频准备 | 用准确正文、附件、参数检查当前包；按已定权限交接或提交，路线选择不赋予提交权限 |
| 结果与返修 | 看实际结果及声音，按真实区间、问题与用户要求修订，候选和采用分开 |

视觉定调属于文字与设计阶段的前置工作，不另增制作阶段。旧项目采用风格直接沿用；已进图稿或视频阶段时补同步已有选择，不撤销历史进度或要求重复批准。

修改以实际影响为准，制作进度、内容版本和可用性分开。可以回看或补做早期内容，但不自动退阶段、清空原决定、重复确认；不规定阶段永远不能变，也不保证历史授权在新范围永久成立。真正新增目标、关键取舍或越出权限才处理对应决定，独立工作继续。

在已有制作范围内用 `revise` 同步当前受影响文档和记录，记录用户反馈 `evidence`。这不是文字和图片的强制绑定：只改声音、参考或其他输入时，同样按真实依赖更新。新增镜头需要判断原路线是否适用；适用时在 `route_reuse_evidence` 写理由，不需要另问用户一次。新独立范围不借用旧范围决定。

例如图稿完成后用户改文字并要求全换图片，按已明确修改继续出新候选，不重走文字确认；旧图留历史，新图不继承旧图采用。此例只是检验通用变更逻辑，不把文字与图片绑定，也不限制只有小改才能保持进度。

新规划路线 `planning_only:true` 只表示选择。实际获得绘图或视频准备授权时，分别记录 `image_stage_entry` / `video_preparation_entry`；可以与方案确认在一次 transact 中记录，不另设用户确认。旧路线记录没有该标记时保持旧语义。`prepare` 检查不替用户授权。

来源不可用时注明缺口，继续有可靠依据的路径；不能因为无新案例就重问已定方案。普通修订后可能需要同步生成建议，但不因此撤销仍适用的选择。技术输入一致性照常核对，不能因免重复审批而忽略新输入。
